# Құқық қызметі (entitlement API)

Сайттың өзі бұрынғыдай статикалық күйде қалады. Бұл қызмет статикалық хост
істей алмайтын жалғыз нәрсе үшін бар: **әр оқушыға бөлек, беру-бермеу шешімін
қабылдау**.

```
GET  /health                     не бапталған (құпия деректер жоқ)
GET  /v1/me                      осы оқушының жарамды сатып алулары
GET  /v1/content/{book_id}       ақылы кітаптың JSON-ы, құқығы болса
GET  /v1/file/{book_id}/audio    Listening трегі үшін қолтаңбалы R2 сілтемесі
POST /v1/admin/grant             құқық беру      (ADMIN_TOKEN)
POST /v1/admin/revoke            құқықты алу     (ADMIN_TOKEN)
POST /v1/webhook/payment         төлем келді     (WEBHOOK_SECRET)
```

## Не ақылы, не ақылы емес

**Оқулықтың PDF-і — әрқашан ашық**, кітап ақылы болса да. Бұл әдейі: адам
кітапты парақтап көріп, жаттығуларының ақшасын төлеуге тұра ма-жоқ па, соны
өзі шешеді. Сатылатын нәрсе — кітап емес, оның айналасындағы қозғалтқыш:
бірден тексеру, интервалды қайталау, қателер, статистика, синх.

Сондықтан `/v1/file/{id}/pdf` әдейі 404 қайтарады да, жария жолды көрсетеді.
PDF-ті кейін жабатын болсаң, дәл сол жер қатты құлайды және не өзгертетініңді
көрсетеді.

Listening аудиосы басқаша: ол — кітап емес, жаттығудың материалы, сондықтан
ақылы кітапта ол да ақылы.

## Негізгі ереже

**Ақылы кітаптың JSON-ы `site/data/`-та мүлде жатпайды.** Статикалық файлдың
үстіне қойылған ақылы қабырға — тек безендіру: файлдың атын тапқан кез келген
адам `curl` жасап алады. Сондықтан ақылы файлдар `api/content/`-те тұрады, оны
тек осы қызмет оқиды, әрі құқықты тексергеннен кейін ғана.

Бөлуді `site/tools/split_content.py` істейді, ал не ақылы екенін
`site/tools/tiers.json` шешеді.

```
site/data/<id>.json     тегін   → Pages-ке кетеді, офлайн кэштеледі
api/content/<id>.json   ақылы   → Railway-ге кетеді, шикі күйде ешқашан берілмейді
```

## Іске қосу реті

### 1. Supabase

SQL Editor → `site/tools/supabase_schema.sql`-ды толық орындап шық. Файл
идемпотентті, бұрын орындалған болса да қайта жүргізуге болады —
`entitlements` кестесі мен оның RLS ережесі соңында тұр.

### 2. Railway

Жаңа проект → GitHub репозиторийінен деплой. Түбірдегі `Dockerfile` табылады;
ол образға тек `api/` мен `site/tools/tiers.*` файлдарын салады, яғни 560 МБ
PDF пен аудио образға кірмейді.

Variables (Railway → Variables):

| Айнымалы | Мәні | Міндетті ме |
|---|---|---|
| `SUPABASE_URL` | `https://xxxx.supabase.co` | иә |
| `SUPABASE_ANON_KEY` | Settings → API → anon/public | иә |
| `SUPABASE_SERVICE_KEY` | Settings → API → **service_role** | иә |
| `ALLOWED_ORIGINS` | `https://aqinaq.github.io,http://localhost:8777` | иә |
| `ADMIN_TOKEN` | ұзын кездейсоқ жол | құқықты қолмен беру үшін |
| `WEBHOOK_SECRET` | ұзын кездейсоқ жол | вебхук үшін |
| `R2_ENDPOINT` `R2_BUCKET` `R2_KEY_ID` `R2_SECRET` | Cloudflare R2 | PDF/аудио ақылы болса |

> `service_role` кілті RLS-ті толық айналып өтеді. Ол тек Railway-дің
> айнымалыларында тұруы керек — браузерге де, репозиторийге де ешқашан емес.
> Браузерге баратыны — `anon` кілті, ол `site/supabase.config.js`-те, және ол
> қауіпсіз.

Settings → Networking → **Generate Domain**. Шыққан мекенжайды тексер:

```
curl https://<домен>/health
# {"ok": true, "config": {"supabase": true, ...}, "paid_books": 7}
```

`"ok": false` болса — журналда `config:` деп басталатын жолдар не жетіспейтінін
атап айтады.

### 3. Сайт

`site/api.config.js`:

```js
window.API_BASE = 'https://<домен>';
```

Бос қалдырсаң — қосымша дәл бұрынғыдай жұмыс істейді: құлып та, желі сұрауы
да жоқ. Форк үшін де, жергілікті жұмыс үшін де дұрыс әдепкі күй осы.

### 4. Мазмұнды бөлу

```
python3 site/tools/tiers.py             # қайсысы ақылы екенін көрсетеді
python3 site/tools/split_content.py     # ақылыларын api/content/-ке көшіреді
python3 site/tools/index_json.py        # index.json-ға tier белгісін қояды
```

`--check` тек тексереді, ештеңе жылжытпайды — сол нұсқасы `pages.yml`-де тұр
және ақылы кітап жария артефактке түссе, деплойды құлатады.

## Төлемді қалай қосу керек

Бірінші күні төлем жүйесі **қажет емес** — қолмен беру толық жеткілікті:

```bash
curl -X POST https://<домен>/v1/admin/grant \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"email":"oqushy@example.com","sku":"ielts","note":"Kaspi 12.07, 3900 ₸"}'
```

`days` жазбасаң — мәңгілік (бір реттік сатып алу). `"days": 30` десең — айлық
жазылым. **Дәл сол кесте екеуін де ұстайды**, сондықтан модельді кейін
таңдасаң да, ешнәрсе көшірудің қажеті жоқ. Мерзімі бітпей тұрып жаңартсаң,
қалған күндер жоғалмайды — үстіне қосылады.

Қолмен беру — кейін тасталатын уақытша амал емес. Ол құқық жолын нақты
сатып алулармен тексеріп алудың жолы: провайдер интеграциясын жазар алдында
шынайы төлем қалай көрінетінін білесің.

Провайдер таңдалғанда (Kaspi, Freedom Pay, ePay) оның денесін
`/v1/webhook/payment` күтетін пішінге аудару ғана қалады — қалғанының бәрі
өзгеріссіз тұрады.

## Жергілікті іске қосу

```
python3 -m venv .venv && .venv/bin/pip install -r api/requirements.txt
SUPABASE_URL=... SUPABASE_ANON_KEY=... SUPABASE_SERVICE_KEY=... \
ALLOWED_ORIGINS=http://localhost:8777 \
.venv/bin/uvicorn main:app --app-dir api --reload --port 8000
```

Сайт жағында `window.API_BASE = 'http://localhost:8000';`.

## Әдейі істелмегені

**Ақылы кітап офлайн жұмыс істемейді.** Жауап `Cache-Control: no-store`-мен
келеді, Service Worker оны ұстамайды. Себебі анық: кэштелген кітап жазылым
біткеннен кейін де ашыла берер еді, яғни жазылымнан бас тарту ештеңені
өзгертпес еді. Мұны дұрыс істеу үшін «жалға берілген кілт» (мерзімі шектеулі,
офлайнда N күн жарамды) керек — ол бөлек жұмыс. Тегін кітаптар бұрынғыдай
толық офлайн істейді.

**Клиенттегі `features` тексерісі — қорғаныс емес.** `drill`, `sync`, `export`
тек интерфейсте жабылады; консолі бар адам оны айналып өте алады. Бұл әдейі:
олар мазмұн емес, сондықтан оған сервер сұрауын жұмсаудың мәні жоқ. Мазмұн —
басқа әңгіме, ол әрқашан серверде шешіледі.
