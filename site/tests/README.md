# Тесттер

```bash
node site/tests/run.js
```

Бір команда: серверді көтереді, headless Chrome-ды қосады, алты жиынтықты
жүргізеді, сосын екеуін де жабады. Бәрі өтсе — шығу коды 0.

Бөлек жүргізу керек болса, `run.js` алдымен серверді қосуы керек:

```bash
node site/tests/serve.js 8853 &     # диапазон (Range) сұраныстарын жауап беретін сервер
node site/tests/audit.js            # браузерсіз
node site/match_test.js             # жауапты тексеру логикасы
node site/tests/app_e2e.js          # (Chrome 9333 портында тұрсын)
```

## Не тексеріледі

| Файл | Не істейді |
|---|---|
| `audit.js` | Браузерсіз: екі тілдің кілттері, кітап↔дерек сәйкестігі, кілт қақтығысы, дыбыс файлдары, sw.js қабығы, деңгей тесті |
| `../match_test.js` | Жауапты салыстыру: 13 кітаптың бүкіл кілтіне қарсы, дұрысын қабылдай ма және қате жауапты қайтара ма |
| `app_e2e.js` | Кітапхана, кітап, жауап беру, қателер мен статистика, сессия, сөз карталары, сөздік, деңгей тесті, іздеу |
| `device_e2e.js` | Телефон (390 × 844), IELTS жауап парағы, офлайн (Service Worker), пернетақта мен қолжетімділік |
| `admin_e2e.js` | Аккаунт панелінің админ жағы, `#/users` және жазылым беру/алу |
| `paywall_e2e.js` | Ақылы қабат: құлып, бағалар, жазылған адамға кітаптың ашылуы, мерзімі біткен жазылым, жалған `active` |
| `supamock.js` | Тест емес: соңғы үшеуі бөлісетін жалған Supabase |

## Неге puppeteer жоқ

Node 22-де `WebSocket` глобал, ал бұл тесттерге керегі үшеу-ақ:
`Page.navigate`, `Runtime.evaluate`, `Fetch.fulfillRequest`. `cdp.js` — сол
үшеуін жүргізетін ~140 жол. Билд қадамы жоқ сайтқа 300 МБ тәуелділік қоспау
үшін әдейі осылай.

## Есте ұстайтын тұзақтар

Бәрі де бір рет уақыт жеп кеткен нәрселер, сондықтан кодта да жазулы тұр:

1. **Тек hash өзгерсе, бет қайта жүктелмейді** — `Page.loadEventFired` келмейді
   де, күту мәңгі тұрып қалады. `goto()` сондықтан әр навигацияға бірегей
   `?t=` қосады.
2. **Service worker-ді ұстап қалу мүмкін емес** — ол беттің желі контекстінен
   тыс жүктеледі, орнатылады, клиентті алады, сосын index.html `controllerchange`
   бойынша бетті қайта жүктеп, ашық терезені жуып кетеді. Офлайн тестінен
   басқасының бәрі `delete Navigator.prototype.serviceWorker` жасайды.
3. **Әр сценарийге өз браузер контексті** — сессия да, прогресс те
   localStorage-та, әйтпесе алдыңғы сценарийдің логині келесіге ауысады.
4. **`localStorage`-ты жүктеуден кейін сеппе** — қайта жүктеу `pagehide`-ты
   іске қосады да, app.js өзінің бос күйін үстінен жазып жібереді.
   `Page.addScriptToEvaluateOnNewDocument` арқылы сал.
5. **`Fetch.enable` үлгісі `https://*.supabase.co/*` болсын** — `*supabase.co*`
   деген `supabase.config.js`-ке де сәйкес келеді де, баптау `{}` болып
   қайтады, аккаунт түймесі мүлде шықпайды.
6. **Имитацияланған Supabase шақырулары preflight-тан өтеді** (кросс-домен +
   `apikey` тақырыбы): `OPTIONS`-қа 204 және
   `access-control-allow-headers: *` жауап бер, әйтпесе браузерден ештеңе
   шықпайды.
7. **`python3 -m http.server` жарамайды**: ол `Accept-Ranges` жібермейді және
   206 қайтармайды, ал pdf.js диапазонды тек бірінші жауапта сол тақырыпты
   көрсе ғана сұрайды. Сондықтан `serve.js` бар.
8. **Ақылы кітап `site/data/`-та жоқ** — сондықтан оны ашатын кез келген
   сценарийге жазылым керек: `supamock.js`-тегі `signedIn(conn, {access: LIVE})`
   `book_content` сұрауына `content/`-тен оқып жауап береді. Жазылымсыз
   сценарийде `fetch('data/<ақылы>.json')` 404 қайтарады — бұл дұрыс жауап.
9. **Chrome эмуляциясы PDF-ті шындай көрсетпейді** — `mobile: true` артында
   да үстелдік PDF плагині жұмысын жалғастырады. Макет үшін сен, плагинге
   тәуелді мазмұн үшін сенбе (`site/README.md`, `pdfview.js` бөлімі).

## Chrome қайда

`cdp.js` бірнеше әдеттегі жолды қарайды (macOS-тағы Google Chrome / Chromium,
Linux-тағы `google-chrome` / `chromium`). Табылмаса, тізім қате мәтінінде
шығады — `cdp.js`-тегі `CHROME` массивіне өз жолыңды қос.
